# JFrog Snippet Detection Demo — C++ File Utility Tool

A sample C++ project that intentionally incorporates code snippets from well-known open-source libraries to demonstrate **JFrog Snippet Detection** via the JFrog CLI.

---

## What is Snippet Detection?

JFrog Snippet Detection identifies the origin of code snippets in your source code — whether copied from another repository, extracted from an open-source library, or generated by AI — and surfaces the associated **security vulnerabilities** and **license obligations**.

It works **at the function level** using semantic fingerprinting — meaning it detects copied code even if variable names are changed, the code is reformatted, or it was independently reimplemented.

### How It Works

```
  Your Source Code
       │
       ▼
  1. ANALYZE    → Parse functions, examine structural logic and flow
       │
       ▼
  2. FINGERPRINT → Create semantic fingerprint per function
       │
       ▼
  3. SEARCH     → Compare against JFrog Catalog (indexed open-source)
       │
       ▼
  4. REPORT     → Matched repo · License · CVEs · Confidence score
```

- JFrog CLI ≥ v2.95.0
- JFrog Platform (JPD) with Xray + JFrog Catalog access
- Entitlement: JFrog Unified Security bundle or higher
- At least one **Watch** with a security/license policy configured in Xray
- **Conan** package manager (for SCA): `pip install conan`

## Run Snippet Detection via JFrog CLI

### Step 1 — Configure JFrog CLI

```bash
jf c add my-server \
  --url=https://<your-jpd>.jfrog.io \
  --access-token=<your-access-token>

jf c use my-server
```

### Step 2 — Install Conan Dependencies (Required for C++ SCA)

JFrog CLI cannot auto-detect C++ dependencies unless a recognised package
manager manifest is present. This project uses **Conan** (`conanfile.txt`).

```bash
# Install Conan if needed
pip install conan

# Install project dependencies declared in conanfile.txt
# This generates the lockfile that JFrog CLI reads for SCA
conan install . --build=missing
```

Without this step, `jf audit` will print:
```
🔧 Couldn't determine a package manager or build tool used by this project 🔧
No components were found
```

### Step 3 — Run Full Audit with Snippet Detection

```bash
# From the project root directory
jf audit \
  --sca \
  --static-sca \
  --snippet \
  --watches=<your-watch-name>
```

> **Note on `--sbom`:** If your Xray instance shows
> `412 Precondition Failed: "Remediation requires dependencies feature enabled"`,
> omit `--sbom`. Snippet detection works without it.

| Flag | Purpose |
|---|---|
| `--snippet` | Enable snippet detection (source code origin scan) |
| `--sca` | Software Composition Analysis (needs conanfile.txt) |
| `--static-sca` | Static source code analysis |
| `--watches` | Xray watch name for policy evaluation |

### Step 3 — View Results

Results are available in two places:

1. **CLI output** — License violations and security findings printed to terminal
2. **JFrog Platform** — Full scan details at:
   `Administration → Xray → Scans List → [your scan]`

Each matched snippet in the platform shows:
- **Origin repository** (e.g., `github.com/madler/zlib`)
- **License** (e.g., `zlib/libpng License`)
- **CVEs** if the origin has known vulnerabilities
- **Confidence score** — HIGH / MEDIUM / LOW
- **Function name** — which exact function was matched

> **Note:** Scan results are retained for **7 days** before automatic deletion.

## Running via Frogbot (CI/CD)

For automated PR scanning, enable Snippet Detection in:
`Administration → Xray Settings → Indexed Resources → Git Repositories`

Frogbot v3.0+ will automatically scan pull requests and post findings as PR comments.

---

## Key Findings to Expect

### 1. MD5 — Weak Cryptography
`checksum/md5.cpp` uses the MD5 algorithm, which is cryptographically broken.
Snippet Detection will identify the origin and surface related CVEs.
**Fix:** Replace with SHA-256 (`<openssl/sha.h>` or `<cryptopp/sha.h>`).

### 2. CRC-32 from zlib — License Obligation
`checksum/crc32.cpp` is derived from zlib. The zlib/libpng License requires
attribution. Snippet Detection flags the obligation.

### 3. Stack Overflow `trim()` — CC BY-SA 4.0 (Copyleft)
`utils/string_utils.cpp` — the `trim()` / `ltrim()` / `rtrim()` functions are
from a Stack Overflow answer. Stack Overflow content is licensed **CC BY-SA 4.0**,
which is a **copyleft** license. Using it in a proprietary product without compliance
is a license violation. This is one of the most surprising findings snippet detection
surfaces, since most developers don't realize Stack Overflow code carries this license.

### 4. LZ4 Compression Pattern — BSD 2-Clause
`compression/lz_compress.cpp` — sliding window + hash chain pattern matches
LZ4's compression logic. BSD 2-Clause requires attribution and license notice.
